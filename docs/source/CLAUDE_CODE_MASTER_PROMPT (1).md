# PART 1: CLAUDE.md (standing rules)

## Mission
Build EGGA (Envelope-Guarded Gain Adaptation): a deterministic supervisor that lets a learned steering-gain scheduler run safely when friction and steering delay are known only as uncertain intervals. Built on the repo `yxgx06/dem`, evaluated against honest baselines.

Problem statement (do not change without asking): keep lateral tracking bounded and the closed loop stable when tyre-road friction and steering-actuator delay are only known as intervals, without trusting an RL policy outside a pre-verified envelope.

## Facts about the starting repo (verified by audit; do not "fix" these by assumption, re-verify in Phase 0)
- RL is a 6->8(tanh)->4 MLP (92 params) scheduling [Kp, Ki, Kd, Khead] of a steering PID with heading term and curvature feedforward. Slew 0.6 rad/s, saturation 0.5 rad.
- Hand-coded mu/slope rules run after the network and do much of the adaptation.
- mu and slope are ground-truth inputs. There is no estimator.
- The benchmark "MPC" is a fixed PD plus feedforward. A real condensed MPC (Np=15, Nc=5) exists only in `master_bicycle_simulation.m`.
- Benchmarks use hand-typed weights in `rl_adaptive_controller.m`; trained weights in `exported_rl_weights.m` are unused.
- `train_rl_agent.py` actor loss = MSE(actor(s), executed action) x mean(advantage). Not a policy gradient. One seed, 150 episodes.
- `generate_missing_benchmarks.py` Figure 6 is synthetic (random numbers, constrained curve hard-coded to 0). Plot legends hard-code 18.4 / 6.1 / <1.85 cm.
- Plant: 2-DOF bicycle, fixed 10 m/s, linear tyres clipped at mu*Fz, Euler at 100 Hz, no delay, noise or actuator lag.
- Python port measurements to reproduce (single deterministic run, max cross-track error cm): nominal PID 8.5, PD+FF 1.6, RL 1.5. RL diverges at 80 ms steering delay; PID and PD+FF survive to 100 ms; everything diverges at 120 ms. Mass x1.3: 9.8 / 0.8 / 0.8. 12 m/s on the ice stage diverges everything because the reference (2.57 m/s^2) exceeds grip (mu*g = 2.45).
- Prototype supervisor (tau_bar = 100 ms) removed divergence at 80 and 100 ms and raised nominal error from 1.46 to 2.54 cm. Friction side untested.

## Non-negotiable honesty rules
1. Every number, table and figure in any report, README or doc is generated by code from a logged results file. No typed-in results. Figure 6 of the original repo must be deleted or replaced by a real experiment.
2. A hypothesis file (`experiments/preregistered.yaml`) is committed and hashed before the test set is ever run. No tuning on test seeds. Negative results are reported as they are.
3. Never write "provably stable", "guaranteed safe", "ASIL-x", "certified", "production-ready", "novel" or "patentable" unless evidence in the repo supports that exact word. Use "verified under assumptions A1..An" and list the assumptions.
4. Label every result with its status: MEASURED (a script in this repo produced it), ESTIMATED (reasoned, assumptions stated), TARGET (a goal, not a result).
5. Anything synthetic, mocked or stubbed is named as such in code (`synthetic_`, `mock_`) and in the output.
6. If a test fails, fix the cause. Never loosen a threshold, skip a test or weaken an assertion to make it pass without writing the reason in `docs/DECISIONS.md` and flagging it to me.
7. If something cannot be done in this environment (MATLAB, hardware, paid standards), say so and build the closest honest substitute with the limit stated.
8. The RL policy never commands steering. It proposes gain corrections; the supervisor decides.

## Engineering standards
- Python 3.11+, `src/egga/` package, `pyproject.toml`, lockfile (uv or pip-tools), type hints, `mypy --strict` on `supervisor/` and `estimation/`, `ruff`, `pytest`, `hypothesis` for property tests.
- All parameters in YAML configs (`configs/`), no magic constants in code. No absolute paths (the original repo has `D:/Projects/CS_UPDATED/`).
- Determinism: every run takes a seed; results store git SHA, config hash, seed, library versions.
- The plant and the controller must be separate implementations that share no equations or code. The estimator and controller never read plant internals (true mu, true delay) except through an explicit `oracle` flag used only for ablations and labelled in outputs.
- Coverage gates: `supervisor/` 100% branch, `estimation/` and `controllers/` >= 90% line, overall >= 85%.
- Commit at the end of each phase with a message listing the gate evidence. Keep `docs/PROGRESS.md` (what is done, what is measured, what is open) and `docs/DECISIONS.md` (design choices and why, rejected options).
- Use sub-agents for independent work: a **red-team reviewer** that tries to break the supervisor and the evaluation (see Phase 5, 7), and a **claim auditor** that checks every claim in docs against results files.

## Stop and ask me only when
A decision cannot be undone and could reasonably go two ways (changing the problem statement, deleting the original repo files, spending money, using a different license). Otherwise decide, record it in `docs/DECISIONS.md`, and continue.

## Phase 1: Plant fidelity (the plant must be able to hurt us)

Build `plant/` as an independent implementation:
- Variable longitudinal speed (constant-speed mode kept as an option).
- Nonlinear lateral tyre (Pacejka magic formula or Fiala), load-dependent peak, peak = mu*Fz, friction-saturating, parameters in YAML. Quasi-static load transfer from lateral acceleration.
- Steering actuator: first-order lag, rate and angle limits, pure transport delay (configurable, 0-150 ms, fixed and jittered), optional gain loss and bias.
- Sensors: noise, bias, quantisation, dropout, sample delay; separate noise for yaw rate, lateral error, steering angle.
- Friction: constant, step, ramp, patches along the path, split-mu option (flag, for known-failure tests).
- Mass and inertia scaling (x1.0 to x1.9 as a stress range), cornering-stiffness scaling, crosswind input.
- Fix the derivative term: filtered derivative (configurable cutoff) in every controller so the 2 cm noise test measures architecture, not a naive differentiator.

Gate 1: plant validated against textbook cases (understeer gradient, step response, saturation); in the linear small-slip regime it matches the Phase 0 plant within a stated tolerance; every new effect has a test; a plot-free numeric report of plant limits (max lateral acceleration per mu).

## Phase 2: Honest baselines

## Phase 3: Estimators with uncertainty

Build `estimation/` (no neural estimator at first):
- Friction interval [mu_lo, mu_hi] from yaw-rate / lateral-acceleration / steering residuals (EKF or windowed least squares) with an excitation measure. When excitation is low, the interval widens toward the prior. Output also a confidence/quality flag. Define mu_safe = max(mu_min, mu_hat - k*sigma) and justify k.
- Steering-delay bound tau_bar from command-versus-response cross-correlation or model-residual fitting; output an upper bound with a margin, never a point value.
- Mass estimate or bound from longitudinal and lateral response (optional).
- Interface:`Estimate(mu_lo, mu_hi, tau_bar, mass_bounds, quality, timestamp)`; stale or invalid input sets the widest bounds, never the last good value.

Evaluate each estimator on its own: bias, RMSE, convergence time, interval coverage (the fraction of runs where the true value lies inside the interval; target >= 95% on val), behaviour at low excitation, behaviour on a sudden friction drop.

Gate 3: coverage and convergence reported on val with CIs; an explicit list of conditions where coverage fails; estimators never read plant internals (test enforces this).

## Phase 4: Offline envelope verification (plan mode first)

This is the core. Design first, show me the plan, then build.

Build `supervisor/envelope.py` plus an offline tool `tools/build_envelope.py`:
- Grid over (speed, mu_lo, tau_bar, mass). For each cell find the set of gains [Kp, Ki, Kd, Khead] that keep the closed loop stable and well damped with the delay bound. Use the discrete-time augmented linear model (delay as extra states, Pade or state augmentation), eigenvalue / margin analysis, then confirm each accepted cell by nonlinear simulation on the Phase 1 plant over a short stress set. State the margin required (e.g. spectral radius <= 0.97 and delay margin >= 1.2 x tau_bar) and why.
- Demand limits per cell: a_y,max = k * mu_lo * g and a steering-rate limit; reference-feasibility speed cap (if the path's required lateral acceleration exceeds a_y,max, lower speed; never relax the constraint).
- Output: a versioned, hashed table (`envelope_vN.npz` plus a JSON manifest with grid, margins, assumptions A1..An, git SHA). Interpolation must be conservative (take the worst neighbouring cell).
- A written assumptions list in `docs/ASSUMPTIONS.md` (e.g. bicycle model valid below x slip, friction interval contains the truth, delay below tau_bar). The envelope's claim is "stable under these assumptions", nothing more.
- Report cell counts (stable of total) and the conservatism cost: tracking error at matching delay for design bounds 0, 40, 60, 80, 100 ms. (In my prototype: 1.36, 1.51, 1.69, 2.22, 3.46 cm. Reproduce or correct.)

Gate 4: table builds reproducibly (same hash on rebuild); property tests: every gain the table returns is inside a stable cell; interpolation never returns a gain outside the verified set; assumptions documented; conservatism curve generated.

## Phase 5: Runtime supervisor

Build `supervisor/` (pure functions, fixed-size state, no dynamic allocation, written so it ports to C99):
1. Gain projection: nearest verified gain in the envelope for the current (v, mu_lo, tau_bar, mass); gain-rate limiter.
2. Reference-feasibility cap on speed.
3. Health monitor: (a) predicted-versus-measured yaw response residual, (b) steering command-versus-response residual, (c) estimator quality and staleness, (d) RL action rate/magnitude, (e) saturation persistence.
4. Mode manager with hysteresis: nominal, cautious, low-mu, degraded-actuator, fallback, minimal-risk. Latch fallback; define the exact conditions for recovery. Noisy estimates must not cause mode chatter.
5. Fallback controller: a verified classical controller (B1 or B6) selected by the envelope; bumpless transfer.
6. Independent logging: every override, rejection and mode change with a reason code.

Tests: unit tests per rule; hypothesis property tests (supervisor output always inside envelope; unsafe RL proposals never reach the actuator; mode manager never oscillates faster than the hysteresis time under bounded noise); a fuzz test with random estimates, NaN, stale and extreme inputs.

Then launch the **red-team reviewer** sub-agent with this brief: "Break the supervisor. Find inputs, estimator errors, delays or scenarios where the closed loop leaves the verified envelope or the supervisor chatters, rejects a safe action forever, or lets an unsafe one through. Report failing seeds as reproducible tests." Fix what it finds and keep its tests.

Gate 5: all tests green, 100% branch coverage on supervisor, red-team findings fixed or documented as known limits, B4 (classical gains plus supervisor) runs on train and val.

## Phase 6: Learning, done properly

Build `rl/`:
- Gymnasium env wrapping the plant, estimators and supervisor. Observation uses ESTIMATES (mu_lo/hi, tau_bar, quality) and tracking states, never ground truth (the oracle flag exists only for ablation B2).
- Action = bounded delta-K around the verified nominal gains, rate-limited. delta-K = 0 reproduces B4 exactly (test it).
- A correct algorithm: PPO (or SAC) with proper log-probabilities, per-sample advantages and clipping; use stable-baselines3 or a reviewed implementation with unit tests on a toy problem. Do not reuse the original actor loss.
- Reward: tracking, steering effort and rate, a margin term (distance to the lateral-acceleration limit), a delay-robustness term, penalties for supervisor overrides, and a large penalty for leaving the envelope. Log each term separately.
- Domain randomisation over mu profile, delay, mass, noise, path curvature; train and val seeds only.
- At least 20 independent training seeds. Report the spread across seeds, not the best seed.
- Train twice: with the supervisor in the loop and without, for the ablation.
- Export the frozen network (weights, normalisation) for Phase 8; no online learning anywhere.

Gate 6: learning curves for all seeds; delta-K = 0 equals B4; B5 vs B4 on val with paired statistics; the original-actor failure at 80 ms delay reproduced as B3 without supervisor and shown with the supervisor.
